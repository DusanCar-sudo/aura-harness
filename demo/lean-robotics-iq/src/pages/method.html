Adaptation, stated plainly

The preprint studies autonomous coding agents. It contains no robot data, no translation experiment and no localization evaluation. What we take from it is the decision layer — the loop, the gate, the cost inequality, the verifier bound — and we apply it to dataset work. That adaptation is ours to test, and the evidence for it is ours to produce. The paper's audit is not evidence about translation, and we do not present it as such.

01 Recursive learning §5 · the loop

The output of a run changes the distribution of the next run.

An agent that merely acts does not improve. An agent that improves has to close a loop in which its own behaviour becomes data, and that data becomes a change in future behaviour. The loop has four stages; the recursion lives in the fourth. The research was done on coding agents; the descriptions below are the paper's, with our data-work translation in parentheses.

R1 — Execute

A tier attempts the task and emits a trajectory. In our line, one string is attempted: a first-pass producer — model-assisted, human, or both — returns a target string together with its alignment decision, termbase version and confidence.

R2 — Capture

The trajectory is reduced to a typed episode: task, pattern, tier, outcome, usage and wall time in the paper; string id, language pair, artifact type, segment map, producer, verdict and cost in ours. A small, boring, queryable record.

R3 — Consolidate

Episodes are compressed twice. First by statistics — a per-pattern competence estimator that spends no model call, on the principle that a confidence should be a ratio, never a model's opinion about itself. Second by distillation: one dated prose digest of recurring failure modes, unresolved threads and a short forward brief.

R4 — Inject

The digest and the derived lessons are placed into the context of subsequent runs, where they condition the next trajectory. Injected memory participates in the next episode, which is consolidated into the memory injected thereafter. That is what makes the loop recursive rather than merely archival.

Definition 5.2 — recursion operator.
Let D be the distillation map and I the injection map. The recursion operator is
R = I ∘ D,    Mn+1 = R(Mn)
One round is one application. A memory state is a pair (episode corpus, distilled text memory).

Two pathologies, and their countermeasures

Drift. Injected summaries are themselves model output. A summary that states a conclusion more strongly than the episodes support becomes, next round, evidence for that conclusion. The countermeasure is provenance: every derived claim traces to episode identifiers, and the statistical branch is computed from raw episodes, never from previous summaries. Arithmetic cannot drift; prose can.

Collapse. If the agent only ever sees its own conclusions, memory converges to a fixed point that no longer corresponds to the world. The same probe rate ε used by the gate keeps a channel open to unmediated evidence, and a failed verification invalidates the digest rather than being absorbed into it.

Neither countermeasure is a proof of safety. They remove the two cheapest ways for the loop to become confidently wrong.

Fixed points are a proof about an assumption

Proposition 6.13 · contraction of the consolidation loop

If distillation is λ-Lipschitz with λ < 1 and injection is non-expansive, the loop is a contraction.

d(RnM0, M*) ≤ λn d(M0, M*)

Then the loop has a unique fixed point and converges to it; with per-step noise bounded by σ, iterates enter a ball of radius σ/(1−λ). The proof is Banach's theorem. What the paper does not prove is that real distillation has the Lipschitz property — it names it as an assumption, and the conclusion inherits that assumption.

The fourth layer changes the weights

R1–R3 adjust the context in which a fixed model operates. A system that only does that will eventually saturate: no amount of well-chosen context teaches a small model a capability it lacks. The implementation therefore tracks accumulated small-tier failures and raises a fine-tune readiness signal once a threshold Fmin = 20 is crossed. The threshold is a heuristic, not a theorem: twenty failures spread over twenty unrelated patterns is not a training set, it is twenty anecdotes.

02 The Archimedes Principle §4 · the gate

A cheap tier may displace only as much as it has verifiably displaced.

The name is taken from displacement. The cheap tier is allowed to displace as much expensive work as its demonstrated competence can support, and no more. Task difficulty plays the role of weight; demonstrated competence plays the role of displaced volume. No hydrodynamic quantity exists in the system: the analogy organises design intuition, and every operational statement is about the estimator, the gate, the verifier and the two costs — each independently measurable.

Definition 4.1 — alternation policy. Let θ = (m0, τ, ε): a minimum observation count, a competence threshold, and a probe rate. For a task t with similarity neighbourhood N(t):
n(t) < m0  →  permit the cheap tier (learning phase)
n(t) ≥ m0 and ŝ(t) ≥ τ  →  permit
otherwise  →  probe with probability ε, else escalate

P1 — Asymmetry of cost

0 < cS ≪ cL. Empirical and trivially true wherever a first pass is cheaper than a senior review. In the deployment studied, cL is metered remote inference and cS a local model.

P2 — Conditional competence

Small-tier success probability is a property of the task's neighbourhood, not of the task alone; it is estimable from accumulated episodes. This is the substantive assumption, and the one an audit can test.

P3 — Verification before commitment

No small-tier output reaches the user without an independent verifier's acceptance. An architectural invariant, maintained by tool restriction — and in our line, by never letting the producer review its own string.

P4 — Refusal of permanent exile

No neighbourhood is permanently barred from the cheap tier. The probe rate guarantees that evidence, not history, decides admission. A closed gate is not self-correcting: a competent pattern can be excluded forever by early bad luck.

The inequality

For a pattern with cheap-tier success probability p and a verifier with recall ρ and false-accept probability α, define the acceptance probability

q = pρ + (1 − p)α
the probability that a cheap attempt is both correct and accepted.
E[Cgate] = cS + (1 − q) cL
q > cS / cL   ⇔   the gate costs less than always-large

Proposition 4.3 · break-even

The gated policy dominates always-large in expected cost if and only if q > cS/cL.

The proof is two lines of algebra: cS + (1−q)cL < cL ⇔ cS < qcL. The interpretation is the design: a cheap tier carries a task exactly when the fraction of the task it can verifiably carry exceeds its cost advantage. A model a hundred times cheaper than the large tier pays for itself whenever its verified acceptance rate exceeds one per cent.

Cost is only half the question. The quality half is the verifier's false-accept rate, and nothing else — developed below.

What the name does not license

Anti-claims

A1. It is not a claim about model physics. A2. It does not assert that small models suffice — if the measurable subset is empty, the gate stays shut. A3. It is not a compression claim about weights; recursion operates on episodes and text until fine-tuning is explicitly triggered. A4. It confers no quality guarantee by itself; any guarantee is inherited from the verifier.

The bench omits three things the paper treats separately: the fixed cost of verification itself, latency, and pattern sparsity (a gate that has too little evidence to open). 04 The safety envelope §6.2 · Proposition 6.11

The gate is never safer than its verifier.

Let the cheap tier be correct with probability p, the large tier with probability pL ≥ p, and the verifier have false-accept probability α. Then the probability that the system returns an incorrect answer satisfies

P[error] ≤ (1 − p) α + (1 − pL)
A union bound over two branches: an accepted wrong cheap answer, or a failed escalation. With a perfect verifier (α = 0) the bound equals always-large.
Prohibition

The theorem's real content is a prohibition. The gate cannot be safer than its verifier, and any quality gain must come from the verifier acting as a filter. The dangerous configuration is self-verification: estimate α on the model that produced the answer, and a model that is confidently wrong is also confidently approved. The implementation therefore treats the verifier model as a distinct, non-droppable configuration field — inheriting the author model would silently convert verification into agreement.

The bound on system error.

The bound is not a measurement. It says what has to be measured before any cost claim is accepted: the verifier's false-accept rate, on the population that matters, with an independent rater. The audit in the preprint did not establish it; the protocol in §8 makes it Hypothesis 8.3.

05 Why gates fail §6.2 · Propositions 6.14 and 6.16

The warm-up cost is the least glamorous result and the most consequential.

A competence gate is not free at the start; it is inert until patterns recur. If a pattern k arrives with probability πk and the gate can be evaluated only once nk ≥ m0, the expected number of arrivals before it becomes evaluable is m0/πk. For K approximately equiprobable patterns that is Θ(m0K) tasks before any pattern reaches the decision stage.

The audit in the preprint observed the worst case: m0 = 3, K ≈ n = 143, and 0 of 143 tasks reached the decision stage. The maximum neighbourhood size ever attained was two. This is a prediction of the model, not a mystery.

The second failure is stranger. If the cheap tier is invoked but unavailable, and the episode is recorded with attempted = 0, then nk stays 0, the estimator is undefined, and the gate remains in its permissive branch forever. The decision becomes independent of the true competence pk: absence of a backend is recorded as absence of evidence, and no amount of subsequent data can move the system off it.

Domain difference

Our corpus is not open-ended code. Robot instruction datasets are template-dense and closed-vocabulary: the same constructions recur across scenes, and a dataset pass produces hundreds of lines per pattern. That is exactly the recurring-pattern regime in which the gate is reachable — the opposite of the 143-unique-keys stream in the audit. The 2026 translation literature adds a second reason for coarse keys: phrasing diversity matters, since a Greek VLA study found seven phrasings per task roughly halved the penalty from translator overfitting. Pattern keys should be construction-level, not sentence-level.

06 Limits the paper's anti-claims

What the method does not claim.

The preprint's §4.4 and §7.7 are unusually explicit, and they are part of the definition rather than a disclaimer at the end. We keep them on the company site because this site sells verification, and the epistemic bookkeeping should be visible.

  • Audit limit

    It cannot establish that gating saves money, that a 1.5B local model reaches the threshold on recurring patterns, that the verifier is sound, or that consolidation is contractive. There is no arm in which the cheap tier ran.

  • Status

    Preprint, not peer reviewed. The regression benchmark has not been peer reviewed; the pre-registered protocol has not been executed. Numbers on this site come from the deployment audit and from public dataset cards, and are labelled as such.

  • Company claim

    We have not claimed a cost saving. The method gives us a decision rule and a way to instrument it. The protocol below is how a saving would be earned and reported — including if the result is another null.

07 The protocol §8 · pre-registered, not executed

The study that would settle it.

The framework makes falsifiable predictions, and the audit did not test them. The preprint specifies the study in enough detail to be registered before data collection — because a paper arguing for evidence-gated decisions should not leave its own evidence to improvisation.

Four arms

ArmPolicyWhat it isolates
AAlways escalateBaseline
BCompetence gate, ε = 0The gate without exploration
CCompetence gate, ε = 0.05The full system
DAlways attempt cheap; escalate on rejectionThe floor, and the oracle competence

Each arm runs the same task list twice in independently randomised order, on two populations: recurring tasks, deliberately repeated with variation, and open-ended tasks, the natural low-recurrence stream. The two-population design makes Prop. 6.14 testable: the framework predicts a benefit on the first and none on the second. On the open-ended population, a saving larger than 5% would indicate an artifact in the harness, not a working gate — a negative control fixed in advance.

Power

Per-pattern evidence. To estimate pk within η = 0.10 at 95% confidence:
nk ≥ (1 / 2η²) ln(2/δ) ≈ 184 attempts
With K = 100 patterns and N tasks, average attempts per pattern is N/K: tight per-pattern evidence demands N ≈ 18,400 tasks. This is the strongest argument for coarser keys or hierarchical pooling.

Population claims. With within-pair standard deviation σd and non-inferiority margin δ = 0.02:
N ≥ (z0.95 + z0.80)² σd² / δ²
For σd = 0.12 this gives N ≈ 282 paired task instances; the cost hypothesis on log-cost with σd ≈ 0.4 gives N ≈ 64 per arm.

The protocol, task lists, arm assignments, seeds and analysis script are to be deposited and frozen before the first arm runs, with a timestamp, and any deviation reported as a deviation. Raw episode stores and cost ledgers are to be published machine-readable and indexed by episode id, so every number in a results table traces to a record.
