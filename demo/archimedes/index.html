Aura Harness · the verification layer

Try cheap.Check honestly.Keep everything.

Archimedes is the heart of Aura Harness. A small, cheap model attempts the task first. A separate verifier model judges the attempt. If it passes, you have an answer for a fraction of the price. If it fails, the large model answers, and the miss is kept as a training example. Either way, the task returns something.

  • Accepted → answer at small cost
  • Rejected → answer + training pair
  • Not trusted yet → answer from large
  • False accept → the one real loss

01 · How it works

One task, three paths, no dead ends.

Watch tasks flow through the gate. Grey dots are tasks waiting for a verdict. Green ones were accepted. Gold ones were rejected and escalated, and each one leaves a pale training dot behind that flows back to the small model.

01 · GATE

Should the small model try?

The gate keeps a running record per kind of task. Once a kind has enough verdicts and passes often enough to pay off, the small model tries it every time. Before that, a probe (ε) still lets it try now and then, so the gate can learn.

02 · VERIFY

A different model judges

The verifier is never the model that wrote the answer. It checks the attempt and says accept or reject. Its verdict is the only thing that decides what you receive.

03 · KEEP

Nothing is thrown away

A pass is an answer. A fail goes to the large model, and the task, the miss and the fix become a training pair. The small model gets better on exactly the tasks it failed.

02 · Why the gate is loose

Loose on the way in. Strict on the way out.

Most cascades guard the entrance: the small model only tries when someone is sure it will succeed. Archimedes lets it try early and often, because a failed try is not wasted. It costs one cheap call and buys a labelled example. The strictness lives in one place only: the verifier that decides what gets delivered.

Four of the five rows end with a correct answer. Two of them also leave a lesson behind. Only the last row is a true loss, and its rate is set by one number: how often the verifier accepts a wrong answer (α). That is why the verifier is the one part we never loosen.

A gate that is too strict starves instead. If the small model is never allowed to try, the gate never sees a verdict and can never learn to trust it. That is exactly what our own audit found (see Evidence), and it is why the probe ε exists.

Every task returns either an answer or a lesson. The only thing we guard is what we deliver.

03 · The one rule

The gate is never safer than its verifier.

The paper proves a simple bound. Because a rejected attempt always falls through to the large model, the only extra errors the gate can add are the wrong answers its verifier waves through.

P[error] ≤ (1 − p)·α + (1 − pL)p = small model accuracy · α = verifier false-accept rate · pL = large model accuracy
pays off when q > cS / cLq = pρ + (1 − p)α, the chance an attempt is accepted · ρ = verifier recall
  • The verifier is a distinct model. A model never grades its own work.
  • Rejection is cheap. It costs one small call and returns a training pair.
  • Trust is earned per kind of task, from verdicts, not assumed.
  • A probe keeps the door ajar so a good pattern can't be locked out by early bad luck.

05 · Evidence, honestly

What our own logs actually showed.

We audited every Aura Code episode from 13 September to 17 October. The result was negative, and it is the reason this design looks the way it does.

1,225real episodes audited
1.049×10⁹tokens in the window
0 / 153decisions where the cheap tier was tried

The gate was too strict to ever open. It waited for evidence before letting the small model try, but evidence only comes from tries. In the cost ledger, 0 of 143 tasks ever reached the minimum evidence. The paper calls this cold-start non-identifiability: attempts that never happen are never recorded, so the gate can't learn why they didn't happen.

The repair is the loose entrance: the probe ε. It guarantees a steady trickle of attempts, and with the verifier guarding the exit, each one returns an answer or a lesson.

What we don't claim. The paper is a preprint and has not been peer reviewed. The cheap tier has not yet fired in production, so no cost savings are claimed here. The evaluation protocol is pre-registered and has not been run yet. The simulator above illustrates the model's math; it is not a measurement.
